## 三、收尾顺序建议

1. **先解锁环境**：提 `muse-dev → main` 的 PR，触发首次 CI，让新增表第 7 条的 DB 用例跑起来。新增表第 2 条和优化表第 4 条也都依赖这一步。
2. **只需要拍板的条目**，可以在一次评审会上集中确认：优化表 2、3、6、7、8、9、11，新增表 1、4、5、6。
3. **本机就能直接做**：优化表 10（拆分 `store/yt.go`）、优化表 12（`useTranslate` 单测）；新增表 3 只需要改文档状态。
4. **需要排期的较大工作**：优化表 1（SSR 直出）→ 优化表 4（油管合并，CI 跑绿之后）→ 新增表 2（E2E）→ 优化表 5（数据流水线三阶段，需要审批）。
